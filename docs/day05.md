# Day 05 - Admin 모드 + NPC 대화 시스템

## 오늘 배운 것
- **useRef를 이용한 React-Phaser 실시간 값 동기화**: state 변화를 Phaser 로직에서 즉시 반영하는 패턴
- **키보드 이벤트를 React에서 직접 감지**: window.addEventListener로 Phaser 밖에서도 키 입력 처리
- **여러 useEffect의 역할 분리**: Phaser 게임용 / state 동기화용 / 키 입력 감지용을 각각 분리
- **대화 시스템 기초**: 배열 순환(모듈로 연산)으로 여러 대사를 순서대로 보여주는 방법

## 오늘 한 것

### 1. Admin 모드 (개발/테스트용 패널)
'P' 키로 토글되는 관리자 패널 구현

React state와 Phaser 로직을 연결하기 위해 useRef 활용:
- godMode(state)가 바뀌면 godModeRef.current도 함께 갱신
- Phaser의 충돌 콜백 안에서는 godModeRef.current를 확인해 무적 여부 판단

이렇게 하는 이유는, Phaser 코드(useEffect 안)는 클로저 특성상 state의 "최신값"을 직접 참조하지 못하기 때문에, ref를 다리로 사용함

### 2. NPC 시스템 구축
NPC 데이터를 별도 객체로 관리 (ENTITY_TYPES와 유사한 패턴)로 이름, 색상, 대사 목록을 포함시킴

E 키로 NPC와 상호작용:
- 매 프레임 플레이어와 NPC 사이의 거리를 계산해 근처에 있는지 판단
- 근처에 있고 E키를 누르면 대사 표시
- 대사 인덱스를 순환시켜(모듈로 연산) 여러 대사를 순서대로 보여줌

### 3. 대화창 UI
화면 하단 중앙에 고정된 말풍선 스타일 대화창을 만들고, 3초 후 자동으로 사라지도록 setTimeout 처리

## 추가 트러블슈팅 2 - 넉백 버그

### 문제 1: 늑대에게 밀리면 계속 밀려나는 현상
넉백 시 캐릭터에게 부여한 속도가 계속 유지되면서, 여러 늑대가 동시에 
부딪힐 때 캐릭터가 화면 끝까지 밀려나는 현상 발생

원인: setVelocity로 넉백 속도를 준 후, 이를 되돌리는 처리가 없어서 
다음 프레임에도 그 속도가 그대로 유지됨

해결 시도: isKnockedBack 상태 변수를 추가하여, 넉백 중 0.2초 동안은 
이동 입력을 무시하고 넉백 속도를 유지하도록 처리

### 문제 2: 넉백 중 스페이스바/E키 등 모든 입력이 반응 안 함
원인: isKnockedBack 조건문의 괄호 범위가 의도한 것보다 넓게 잡혀서, 
이동 로직뿐 아니라 채집/공격/NPC 상호작용 로직까지 조건문 안에 
포함되어 버림

해결: 괄호 범위를 정확히 이동 처리 부분만 감싸도록 재조정하여, 
넉백 중에도 다른 조작(스페이스바, E키)은 정상 작동하도록 수정

### 오늘의 교훈
if문으로 특정 로직을 감쌀 때는 의도한 범위와 실제 괄호가 
닫히는 위치가 일치하는지 반드시 재확인해야 함. 코드가 길어질수록 
괄호 매칭을 눈으로 놓치기 쉬우므로, 들여쓰기를 기준으로 
범위를 시각적으로 확인하는 습관이 중요함
