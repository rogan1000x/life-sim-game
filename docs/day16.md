# Day 16 - 용병 등급 + 승급 시험 시스템 (주점 4단계, 완료)

## 오늘 배운 것
- 여러 단계로 이루어진 등급/티어 시스템은, 각 등급에 order(순서 숫자)를 부여해두면
  "다음 등급 찾기(order+1)", "등급 비교(order 크기 비교)" 같은 로직을 훨씬 간단하게
  구현할 수 있다는 것 - 이름 문자열끼리 비교하는 것보다 훨씬 안전하고 확장하기 쉬움
- 새로운 gameConfig.js export를 추가할 때마다 GameScene.js/App.js의 import 문에
  그 이름을 추가하는 걸 반복적으로 빠뜨렸다는 것을 다시 한번 확인함 - 이제는 새 데이터를
  추가하는 작업의 마지막 단계로 "import 문 확인"을 습관화할 필요가 있음

## 오늘 한 것

### 1단계: 용병 등급 시스템 설계 및 구현
주점(용병 길드) 마지막 단계로, 리나에게 직접 승급 시험을 보는 방식의 등급 시스템을
구현함. RANK_TIERS에 초급/중급/고급/특급 4단계를 정의하고, 각 등급마다 승급에 필요한
레벨, 완료 퀘스트 수, 시험비(골드)를 설정함. GameScene에 rank(현재 등급)와
questsCompletedCount(누적 퀘스트 완료 횟수) 상태를 추가하고, turnInQuest()에서
완료할 때마다 이 횟수가 누적되도록 연결함

### 2단계: 등급별 퀘스트 잠금
기존 퀘스트 5개에 minRank: 'bronze'를 부여해 누구나 받을 수 있게 유지하고, 중급/고급
전용 상위 난이도 퀘스트 2개(늑대 무리 소탕, 대규모 늑대 토벌)를 추가함. 등급이
낮으면 주점 퀘스트 목록에서 🔒 표시와 함께 잠긴 상태로 보이도록 처리

### 3단계: 승급 시험 구현
takeExam() 함수가 다음 등급의 조건(레벨/완료 퀘스트 수/시험비)을 순서대로 확인하고,
하나라도 부족하면 어떤 조건이 부족한지 알림으로 알려주도록 구현. 조건을 모두
만족하면 시험비를 지불하고 즉시 승급됨. 주점 UI에 현재 등급, 다음 등급 조건,
승급 시험 버튼을 추가함

### 4단계 (트러블슈팅): import 누락 반복
RANK_TIERS를 gameConfig.js에 추가한 뒤, GameScene.js의 import 문에 추가하는 걸
또 빠뜨려 'RANK_TIERS' is not defined 에러가 발생함. 이전에도 여러 차례 반복된
패턴이라, 앞으로 새 데이터를 gameConfig.js에 추가할 때는 관련된 모든 파일의
import 문을 함께 확인하는 것을 원칙으로 삼기로 함

### 5단계: 전투 직업 시스템 도입
전사/궁수/마법사/성직자/도적/소환사 6개 직업을 설계함. 직업마다 시작 스탯(공격력/체력/
이동속도)이 다르고, 도적은 밤에 추가 공격력(nightAttackBonus), 소환사는 동료 전투
보너스 배율 증가(companionBonusMultiplier)라는 고유 특성을 가짐. CLASS_TYPES에
직업 데이터를 정의하고, 처음엔 게임 시작 화면에서 직업을 고르는 방식으로 구현했다가,
"리나에게 처음 등록할 때 직업을 정하는" 흐름이 스토리상 더 자연스럽다는 피드백에 따라
주점의 용병 등록 화면으로 옮김. 직업이 없으면 주점의 등급/퀘스트 섹션 대신 직업 선택
카드가 뜨고, 하나를 고르면 즉시 스탯이 적용되며 이후 등급/퀘스트를 이용할 수 있게 됨

### 6단계: Admin 초기화 기능 추가
여러 직업을 테스트해보기 편하도록, Admin 패널에 레벨/경험치/스탯포인트/직업을
한 번에 초기화하는 버튼을 추가함. 골드/인벤토리/장비/퀘스트 진행도/동료 등
성장과 무관한 데이터는 건드리지 않도록 범위를 제한함. 되돌릴 수 없는 동작이라
브라우저 기본 확인창(window.confirm)으로 실수 방지 처리를 추가함

### 7단계: 기본 공격 이펙트 + 직업 스킬(패시브 트리) 시스템
공격이 몬스터에 명중할 때마다(처치 여부와 무관하게) 짧은 슬래시 이펙트가 나오도록
createAttackSlashEffect()를 추가해 타격감을 보강함

이어서 스킬 시스템의 기반을 설계함. 액티브 시전형 스킬은 다음 단계로 미루고, 이번엔
"레벨업마다 받는 스킬 포인트로 직업 전용 패시브를 강화하는" 방식으로 구현함. 이
구조는 나중에 장비의 부가 옵션이 스탯을 더해주는 기능과 같은 effectType 체계
(attack/speed/maxHp)를 재사용할 수 있도록 의도적으로 맞춤. CLASS_SKILLS에 전사
스킬 2종(베기 숙련: 공격력, 불굴의 의지: 최대체력)을 우선 채우고, 나머지 5개
직업은 빈 배열로 자리만 잡아둠. 스킬 포인트는 statPoints와 별도로 레벨업 시 함께
지급되며, upgradeSkill()이 레벨 상한(maxLevel)까지 하나씩 강화하도록 처리함

## 완성된 시스템 요약 (Day 16 전체)
- 용병 등급(초급/중급/고급/특급)이 생기고, 사이드바에 현재 등급이 표시됨
- 리나에게 승급 시험을 볼 수 있고, 조건 부족 시 무엇이 부족한지 알려줌
- 상위 등급 전용 퀘스트가 낮은 등급에서는 잠겨서 안 보이거나 잠금 표시됨
- 이것으로 주점(용병 길드) 시스템 1~4단계(건물/휴식/음식, 퀘스트, 동료 고용, 등급)가 모두 완료됨
- 전투 직업 6종이 생기고, 리나에게 첫 등록 시 직업을 고르는 방식으로 자연스럽게 연결됨
- Admin 패널에서 레벨/직업을 안전하게 초기화하고 재시도할 수 있음
- 공격 시 슬래시 이펙트로 타격감이 보강되고, 전사 직업에 한해 스킬 포인트로 패시브를
  강화하는 시스템의 기반이 마련됨 (나머지 5개 직업 스킬은 다음 세션에 채울 예정)

## 다음 할 것

### 1. 늑대 전용 필드 분리
지금은 늑대가 마을(마을 주민이 있는 지역)에도 그대로 돌아다니고 있어, 생활 공간과
전투 공간이 뒤섞여 있음. 마을과 분리된 별도의 "필드/사냥터" 구역을 만들어서
늑대(및 향후 추가될 몬스터)는 그쪽에만 배치하고, 마을은 안전지대로 만드는 방향을 논의할 것.
구현 방향 후보: 별도의 Phaser Scene 분리 / 같은 맵 안에서 좌표 구역만 나누기 / 필드
입구 오브젝트(문, 경계선 등)로 진입 연출.

### 2. 근본 스탯(1차 스탯) 시스템 도입
지금의 attackPower/maxHp/moveSpeed 같은 "결과 스탯" 대신, 아래 5개의 근본 스탯을
두고 그 수치에 따라 결과 스탯들이 계산되는 구조로 확장 예정:
- 근력: 공격력 상승 (기본 피해량 결정)
- 활력: 체력 및 방어력 상승
- 민첩: 치명타 확률 및 치명타 피해 상승
- 지능: 추가 마력 및 재사용 대기시간 감소
- 감각: 정밀도 상승 (적에게 주는 최소 피해량 증가)

이 작업은 방어력/치명타/마력/정밀도처럼 지금 아예 없는 전투 공식들을 새로
설계해야 해서 규모가 큼. allocateStat()과 스킬 시스템(effectType 체계),
장비 효과 시스템 전부가 이 근본 스탯 구조에 맞춰 재설계될 가능성이 있어,
다음 세션에서 범위를 나눠 단계적으로 진행할 것
