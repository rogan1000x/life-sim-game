# Day 14 - 상인 거래 시스템 + 화폐 세분화 + 시세 그래프 + 로그 UI 개선

## 오늘 배운 것
- 자동으로 골드를 지급하던 방식에서 "채집만 하고, 상인에게 팔아야 돈이 됨" 방식으로
  바꾸면 NPC 상호작용에 실질적인 목적이 생긴다는 것
- 재고량과 가격을 반비례 관계로 엮으면(재고 적음=비쌈, 재고 많음=쌈) 간단한 수식만으로도
  그럴듯한 시장 경제처럼 보이는 시스템을 만들 수 있다는 것. 다만 배율에 상한/하한을
  걸어두지 않으면 가격이 극단적으로 치솟거나 폭락할 수 있어 범위 제한이 필요하다는 것
- 화면에 보여줄 화폐 단위(골드/실버/구리)와 내부 계산에 쓰는 숫자를 분리해서,
  내부적으로는 항상 하나의 정수(구리 단위)로만 계산하고 표시할 때만 변환하면
  계산 로직이 훨씬 단순해진다는 것
- 여러 개를 한 번에 사고팔 때, 한꺼번에 계산하지 않고 "한 개씩 반복하며 그때그때
  가격을 다시 계산"해야 재고 변화가 뒤쪽 개수의 가격에도 정확히 반영된다는 것
- 재고가 0이 되는 걸 막기 위해 최소값을 1로 강제해두면, "진짜 품절"이 표현이
  안 된다는 것 - 실제로 0까지 떨어지게 두고, 나눗셈 같은 계산 부분에서만
  0으로 나누기 에러를 피하기 위해 최소 1로 취급하는 것으로 수정해야 함
- 문자열이 비어있으면(`''`) 자바스크립트에서는 false로 취급된다는 것을 이용해
  `조건 && <JSX>` 형태로 "조건이 있을 때만 화면에 보여주는" 조건부 렌더링을 할 수 있음
- CSS의 flexDirection: column-reverse를 쓰면 새로 추가된 항목이 반대쪽 끝에
  쌓이게 만들 수 있어서, "알림이 화면 아래에서 위로 쌓이는" 자연스러운 효과를 낼 수 있음
- 코드 조각을 주고받을 때, 실제 파일 상태와 어긋난 채로 위치를 짚으면 계속 수정이
  어긋난다는 것을 여러 번 겪음 - 이후로는 수정 전 실제 파일 전체(또는 관련 함수 전체)를
  먼저 받아 확인하는 방식으로 전환해 정확도를 높임

## 오늘 한 것

### 1단계: 상인 거래 시스템 설계 논의
자원/몬스터를 채집·처치하면 즉시 골드가 들어오던 기존 방식을 없애고, 대신 상인(NPC)에게
아이템을 가져가 팔아야 골드를 받는 구조로 바꾸기로 함. 거래 가능 대상도 상점에서 산
장비/포션을 포함해 전부 사고팔 수 있게 확장하기로 함

### 2단계: 재고 기반 시장 경제 구현
SHOP_ITEMS에 basePrice(기준 가격)를 두고, GameScene에 marketStock(아이템별 재고)을
추가함. getMarketPrice()가 재고와 기준치(10)를 비교해 실시간 가격을 계산하며,
배율을 0.4~2.5배 사이로 제한함. buyItem/sellItem을 개수만큼 반복 계산하는 방식으로
재작성하여, 여러 개를 사고팔 때 뒤로 갈수록 가격이 점점 바뀌도록 구현. 채집/처치 시
자동 골드 지급 로직은 제거하고, 대신 아이템을 인벤토리에만 쌓이게 수정함

### 3단계 (트러블슈팅): 코드 반영 상태 어긋남
여러 차례에 걸쳐 안내한 "찾을 부분" 코드가 실제 파일과 일치하지 않는 문제가 반복됨
(equipped 복원 코드, 상점 목록 UI 등). 결국 GameScene.js와 App.js 전체 코드를 받아
실제 상태를 확인하는 방식으로 전환하여 정확한 수정 위치를 다시 잡음. 이 과정에서
GameScene.js에 formatCurrency import가 빠져있던 실수도 함께 발견해 수정함

### 4단계: 화폐 세분화 (골드/실버/구리)
gold 변수를 없애지 않고 "구리 단위"로 재해석하는 방식을 택함. 1골드=100실버,
1실버=100구리 환산 규칙만 두고, formatCurrency() 헬퍼가 화면 표시 시점에만 G/S/C로
쪼개 보여주도록 구현. 기존 가격 숫자를 하나도 안 건드리고 표시 방식만 바꿔서
경제 밸런스에 영향 없이 적용함

### 5단계: 시세 그래프 추가
recharts 라이브러리를 새로 설치하고, GameScene이 2초마다 모든 아이템의 가격을
priceHistory 배열에 기록(최근 30개까지만 유지)하도록 구현. 상점 UI에 아이템별
📈 버튼을 추가해 누르면 최근 가격 변화를 꺾은선 그래프로 보여주도록 함

### 6단계: 상인 재고 표시 및 구매 제한
지금까지는 재고가 최소 1 밑으로 안 내려가게 막아둬서 사실상 무한 구매가 가능했던 점을
지적받아 수정함. 재고가 실제로 0까지 떨어질 수 있게 하고, 0이면 "품절"로 표시하며
구매 버튼도 비활성화되도록 구현. 계산식에서 0으로 나누는 에러만 방지하도록 처리를
분리함(표시/구매 제한용 값은 진짜 0, 계산용 값만 최소 1로 취급)

### 7단계: UI 자잘한 개선
- 재료 아이템(나무/돌/토끼/늑대 부산물)에 효과가 없어 상점에 빈 괄호("나무 ()")로
  보이던 문제를 발견, getEffectLabel()에 재료용 문구를 추가하고 조건부 렌더링으로
  효과 문구가 아예 없을 때는 괄호 자체를 숨기도록 수정
- 이벤트 알림(로그)이 화면을 많이 가린다는 피드백에 따라, 최대 4개까지만 표시되도록
  제한하고 화면 하단으로 위치를 옮기고 크기도 줄임. 이후 요청에 따라 위치를 화면
  왼쪽 아래로 재조정함

## 완성된 시스템 요약 (Day 14 전체)
- 채집/사냥으로는 아이템만 얻고, 상인에게 팔아야 골드를 받는 경제 구조로 전환됨
- 모든 아이템(포션/장비/재료)을 상인에게 사고팔 수 있고, 재고에 따라 실시간으로 가격이 변동함
- 재고가 0이 되면 품절 표시와 함께 구매가 실제로 막힘
- 화폐가 골드/실버/구리로 세분화되어 표시됨
- 상점에서 아이템별 최근 시세 변화를 그래프로 확인 가능
- 이벤트 알림이 화면 왼쪽 아래에 최대 4개까지만 작게 쌓이도록 개선됨
