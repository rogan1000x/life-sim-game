# Day 19 - 동료 이름/개성/특성 확장

## 오늘 배운 것
- 데이터의 키(id) 값을 바꾸면, 기존에 그 키를 참조하고 있던 저장 데이터(localStorage 등)는
  자동으로 갱신되지 않기 때문에 "예전엔 있었지만 지금은 없는 id"를 참조하다 생기는
  undefined 에러가 날 수 있다는 것. 이런 경우 불러오기 시점에 예전 id를 새 id로
  매핑해주는 마이그레이션 코드를 추가하면, 기존 플레이 데이터를 잃지 않고 안전하게
  구조를 바꿀 수 있다는 것
- 어떤 값을 참조하는 함수라도, 데이터에 없는 값이 들어올 가능성이 있다면 기본값으로
  방어(`|| { name: '동료' }` 같은 형태)해두면, 예상 못한 상황에서도 최소한 에러 없이
  기능이 동작하게 만들 수 있다는 것
- 같은 스프라이트 이미지라도 setTint로 색조를 다르게 입히면, 새 그림을 구하기 전까지
  최소한의 시각적 구분을 만들 수 있다는 것

## 오늘 한 것

### 1단계: 동료 4명으로 확장 (이름/개성/특성 부여)
기존에 "떠돌이 동료" 하나뿐이던 동료를 로이(성실한 여행자, 밸런스형)/미라(대담한
전직 용병, 공격형)/세인(신중한 은둔 학자, 방어형)/파이(쾌활한 방랑자, 성장형)
4명으로 확장함. 각자 능력치 성향을 다르게 주고, 개성 있는 특성을 하나씩 부여함:
- 미라: critBonus - 20% 확률로 기본 공격에 추가 피해(2배)가 터짐
- 세인: damageReduction - 몬스터에게 받는 피해를 25% 감소시킴
- 파이: expBonus - 획득하는 경험치가 1.5배로 늘어남 (성장이 빠름)

고용 시 각자 다른 고용 대사(hireLine)가 뜨도록 하고, 새 전용 그림을 구하기 전까지는
같은 스프라이트에 서로 다른 색조(tint)를 입혀 최소한의 외형 구분을 만듦

### 2단계 (트러블슈팅): 예전 저장 데이터의 'traveler' id 참조 에러
동료 id를 traveler에서 roy/mira/sein/pie로 바꾸면서, 예전에 이미 동료를 고용해둔
저장 데이터에는 여전히 hiredCompanionId: 'traveler'가 남아있어 COMPANION_TYPES에서
찾지 못해 undefined.name을 읽으려다 에러가 발생함. 저장 데이터를 불러오는 시점에
'traveler'를 'roy'로 자동 변환하는 마이그레이션 코드를 추가하고, dismissCompanion()도
데이터를 못 찾는 경우 기본 이름으로 안전하게 처리하도록 방어 코드를 추가해 해결함

## 완성된 시스템 요약 (Day 19 전체)
- 동료가 이름, 개성 설명, 색조로 구분되는 4명으로 늘어남
- 동료마다 고유한 전투 특성(치명타 확률/피해 감소/경험치 배율)이 실제로 작동함
- 예전 저장 데이터도 에러 없이 자동으로 새 구조에 맞춰 이어짐
