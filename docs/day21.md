# Day 21

## 1. 도적 Q키(은신)가 안 먹히던 버그

**증상**: 도적으로 Q를 누르면 은신이 아니라 "사거리 안에 몬스터가 없어요"만 뜨고 아무 일도 안 일어남.

**원인**: `useActiveSkill()`에서 도적이 warrior/archer랑 같은 조건문에 묶여 있었음.
Q가 "은신"이 아니라 "근처 타겟에게 즉시 공격"으로 동작했고, 근처에 몬스터가 없으면 실패 메시지만 뜸.
은신→기습(치명타) 로직(`rogueAmbushReady`)은 근접 공격 코드에 이미 있었는데, Q키가 그걸 켜주지 않고 있었음.

**수정**:
- 도적을 별도 분기로 분리. Q를 누르면 몬스터 유무와 상관없이 은신 상태(`rogueAmbushReady = true`, 반투명)가 됨.
- `CLASS_ACTIVE_SKILLS.rogue.stealthDurationMs`(5000ms) 동안 공격하지 않으면 자동 해제.
- 다음 근접 공격은 기습 치명타(`ambushMultiplier`)로 들어감.
- 은신 해제 로직을 `breakStealth()` 하나로 통합 (기습 성공 / 피격 / 시간 초과 / 사망 공통).
- 몬스터에게 맞으면 은신이 풀림 ("공격을 받아 은신이 풀렸어요!").
- 자동 해제 타이머를 `rogueStealthTimer`에 저장하고 해제 시 함께 제거
  → 은신 → 해제 → 재은신 시 옛 타이머가 새 은신을 조기 종료시키는 문제 방지.

**관련 파일**: `GameScene.js` (`useActiveSkill`, `breakStealth`, 플레이어-몬스터 overlap, `handleDeath`)

## 2. 용병(동료)과 소환사 정령이 같은 슬롯을 공유하던 버그

**증상**: 용병을 고용한 상태에서 정령을 소환하면(또는 반대로) 이전 유닛 정보가 덮어써져서 둘을 동시에 데리고 다닐 수 없었음.

**원인**: `hireCompanion`과 정령 소환(Q키/테이밍)이 `hiredCompanionId`, `companionSprite`, `companionClass` 등 같은 변수를 공유.

**수정**:
- `this.allies = { mercenary, spirit }` 구조로 상태를 완전히 분리.
- 스프라이트/체력/콜라이더/자동스킬 타이머를 슬롯별로 독립 관리하도록 메서드를 슬롯 기반으로 리팩터링
  (`spawnAlly`, `dismissAlly`, `updateAllyFollow`, `updateAllyFacing`, `allyBasicAttack`,
  `gainAllyExp`, `startAllyAutoSkillTimer`, `useAllyAutoSkill`, `handleAllyKO`).
- 근접 공격 보너스, 성직자 힐 대상 선정도 두 유닛을 모두 고려.
- 따라다닐 때/부활할 때 겹치지 않게 슬롯별 위치 분리 (용병 왼쪽, 정령 오른쪽).
- 세이브 포맷을 `allies: { mercenary, spirit }`로 변경, 예전 세이브는 자동 마이그레이션.
- `syncStatsToReact()`: 기존 키(`hiredCompanionId` 등)는 용병 정보로 유지, 정령은 `spiritCompanionId`/`spiritLevel`/`spiritExp` 추가.

**관련 파일**: `GameScene.js` (동료/정령 관련 메서드 전반)

## 6. 동료(용병)를 여러 명 데리고 다닐 수 있게 변경
- 용병 슬롯을 `MERCENARY_SLOTS = ['mercenary_0','mercenary_1','mercenary_2']`(최대 3명)로 확장.
  정원은 배열에 슬롯 이름만 추가하면 늘어남. 소환사 정령(`spirit`)은 별도 슬롯이라 정원에 포함 안 됨.
- 고용 시 빈 슬롯에 자동 배정, 같은 인물 중복 고용 불가, 정원 초과 시 안내 로그.
- `dismissCompanion(slot)`은 이제 슬롯을 받음 (여러 명 중 누구를 해고할지 지정).
- 유닛별 위치(`getAllyFormationOffset`): 용병들은 왼쪽 뒤에 세로로, 정령은 오른쪽 → 겹치지 않음.
- 로그에 "동료가" 대신 유닛 이름 표시 (`getAllyName`).
- `syncStatsToReact()`: `mercenaries` 배열 + `maxMercenaries` 전달 (기존 `hiredCompanionId` 등 단일 키는 제거).
- `App.js` 주점: 동료 목록(레벨/EXP/HP/해고 버튼) + 남은 자리 있으면 고용 목록 표시.
- 세이브: `allies`가 슬롯 이름별로 저장됨. 예전 `mercenary` 키/단일 `hiredCompanionId` 세이브는 첫 슬롯으로 자동 마이그레이션.
- **버그 수정**: `spawnAlly()`가 레벨/EXP를 항상 1/0으로 덮어써서, 저장 후 다시 불러오면 동료 레벨이 초기화되던 문제
  (Day21 리팩터링에서 생긴 회귀). 이제 저장된 레벨을 유지하고, 최대체력도 레벨 보너스(+10/레벨)를 반영해 복원.

## 7. 플레이어 경험치를 동료/정령과 함께 나눠 받기
- `gainExp()`에서 플레이어가 경험치를 얻으면, 고용 중인 모든 동료(용병들)와 정령도 같은 양을 함께 받음
  (몬스터/채집/퀘스트 보상 전부 해당). 동료 개별 성격(파이의 expBonus 등)은 그대로 적용.
- 비율은 `ALLY_SHARED_EXP_RATIO`(기본 1.0)로 조절 가능 (0.5면 절반).
- `gainAllyExp()`를 `while` 반복으로 바꿔 한 번에 여러 레벨이 오를 수 있게 함 (기존엔 1레벨만 오름).
- `skipSync` 옵션 추가: 여러 유닛에게 연달아 줄 때 화면 갱신/저장이 유닛 수만큼 반복되지 않게 함.
- 기존의 "동료가 직접 공격/스킬을 쓸 때 얻는 경험치"는 그대로 유지 (추가로 더해짐).

## 8. 던전 클리어 후 밖으로 못 나오는 문제 수정
- **원인 후보 정리**: 출구 문에 안내가 전혀 없어서(문 위 글자 없음, E키 안내 없음) 나가는 방법을 알 수 없었고,
  같은 몬스터가 한 프레임에 두 번 처치 처리되면(플레이어+동료 동시 마무리) 남은 몬스터 카운터가 어긋날 수 있었음.
- `checkDungeonCleared()`: 처치 카운터에만 의존하지 않고, 살아있는 던전 몬스터를 직접 세서 0이면 출구를 열어주는 안전장치.
  남은 몬스터 수도 상단 문구에 실시간 표시("남은 몬스터 N마리").
- `defeatMonster()`에 `isDefeated` 가드 추가 → 중복 처치(전리품/경험치 2배, 카운터 2번 깎임) 방지. 리스폰 시 해제.
- 클리어 연출: 화면 번쩍임 + 파티클 + 링 이펙트, 문 뒤에서 반짝이는 빛, 문 위 "🚪 출구 (E키)" 라벨,
  화면 중앙 큰 안내 배너(4.5초 후 페이드아웃), 상단 상시 안내 문구.
- 나가는 방법: 출구 문 근처 E키, 또는 **클리어 후 어디서든 H키(비상 탈출)**. 문에서 멀 때 E를 누르면 안내 로그.
- 나갈 때 번쩍임+파티클 연출, 출구 관련 오브젝트/트윈은 `cleanupDungeonExitObjects()`로 한꺼번에 정리.

## 10. 유대감(Bond) 시스템 - 캐릭터/동료 공용 성장 축 (풀 버전)
전투 레벨(level/exp)과는 완전히 별개의 축으로, "함께 싸운 경험"과 "대화"로만 쌓이는 유대감을 추가했어요.

- **설정**: `gameConfig.js`에 `BOND_CONFIG` 추가 (레벨당 필요 경험치, 전투/대화 획득량, 최대 레벨(10), 레벨당 스탯 보너스).
- **획득 경로**:
  - 동료/정령이 스스로 공격하거나 자동 스킬을 쓸 때마다 소량(`combatGain`) 획득.
  - 주점에서 "💬 대화" 버튼으로 하루 1회 큰 폭(`talkGain`)으로 획득 (`talkToAlly(slot)`).
- **보상**:
  - 유대 레벨이 오를 때마다 그 동료의 공격 보너스 + **플레이어의 공격력/방어력**에도 소량씩 반영
    (`recalculateDerivedStats()`에서 모든 동료의 유대 레벨을 합산해 매번 새로 계산 → 해고하면 자동으로 빠짐).
  - `bondDialogues`(레벨 3/6/10)에 도달하면 "대화" 시 특별 대사가 뜸 (동료마다 다른 대사, 정령은 정령다운 묘사체 대사).
  - 유대 레벨 10(최대) 최초 도달 시 1회성 축하 연출(화면 번쩍임 + 파티클 + 링 이펙트 + 특별 대사 팝업).
- **UI**: 주점의 동료/정령 섹션에 "💗 유대 Lv.N (EXP x/y)"와 "💬 대화" 버튼 추가. 오늘 이미 대화했으면 버튼 비활성화.
- **저장**: 동료별 `bondLevel`/`bondExp`/`bondMaxCelebrated`/`lastTalkedDay`를 세이브에 포함. 동료를 해고하면 유대감도 함께 초기화됨(새로 고용하면 처음부터 다시 쌓임 - 의도된 동작).
- **관련 파일**: `gameConfig.js`(COMPANION_TYPES에 `talkLines`/`bondDialogues` 추가, `BOND_CONFIG` 신설), `GameScene.js`(`gainBondExp`, `talkToAlly`, `celebrateMaxBond`, `recalculateDerivedStats` 보정), `App.js`(주점 UI).

## 11. HP바 개선 - 레벨 표시 + 피격 깜박임
- HP바 오른쪽에 `Lv.N` 작은 텍스트 표시 (슬롯당 Text 객체 하나를 재사용, 매 프레임 새로 안 만듦).
- 동료/정령이 맞으면 `hitFlashUntil`을 세팅해서 0.25초간 바가 100ms 간격으로 하양/원래색 깜박임.
- 집/주점 내부에서는 레벨 텍스트도 함께 숨김 (기존엔 바 Graphics만 clear했음).

## 12. 동료/정령이 전부 똑같이 움직이던 문제 수정
- **원인**: 모든 유닛이 몬스터의 정중앙을 목표로 동일한 속도(200/190/180)로 직진해서, 같은 몬스터를
  공격할 땐 거의 겹치다시피 모이고, 대기 중엔 완전히 멈춰 있어서 "하나처럼" 움직이는 것처럼 보였음.
- **수정**: `ALLY_PERSONALITY` 표로 슬롯별 개성 부여.
  - `attackAngleDeg`: 같은 몬스터를 공격할 때 몬스터를 중심으로 서로 다른 각도에서 접근 (안 겹침).
  - `speedMod`: 이동속도를 0.85~1.15배로 유닛마다 다르게 (완전히 같은 타이밍에 안 움직임).
  - `idlePhase`: 대기 중 사인파 기반으로 아주 살짝 제자리에서 흔들림, 유닛마다 위상이 달라 서로
    다른 타이밍에 흔들림 (완전히 얼어붙어 보이지 않게).
- 용병 3명 + 정령까지 전부 다른 접근 각도/속도/흔들림을 가져서 같은 자리에 뭉치지 않음.

## 13. 직업별 광역(다중 타겟) 스킬 추가 (R키)
- Q키의 기존 액티브 스킬(`CLASS_ACTIVE_SKILLS`)과는 완전히 별개 쿨타임을 쓰는 새 스킬 세트
  `CLASS_AOE_SKILLS`를 `gameConfig.js`에 추가하고 R키에 배정.
- 두 방식으로 구현: `radius`가 있으면 플레이어 주변 반경 안의 몬스터 전부 타격(근접형),
  `maxTargets`가 있으면 가까운 순으로 최대 N마리 동시 타격(원거리형).
  - 전사: 회전 베기 (반경 110, x1.4)
  - 궁수: 다중 사격 (최대 3마리, x1.3)
  - 마법사: 메테오 샤워 (사거리 무제한=화면 전체, x1.6, 쿨타임 15초로 가장 김)
  - 성직자: 심판의 빛 (반경 130, 언데드 x2.2)
  - 도적: 표창 난사 (최대 3마리, x1.2)
  - 소환사: 영혼 파동 (반경 140, x1.3)
- 맞은 대상이 없으면 쿨타임을 소모하지 않음 (Q키 스킬들과 동일한 정책).
- UI: 화면 우하단에 Q 아이콘 옆에 R 아이콘을 나란히 배치, 각자 독립적인 쿨타임 표시.
  ESC 메뉴 키 안내에도 R키 설명 추가.

## 14. 마을 확장 - "마을 외곽 텃밭" 구역 신설 + 전체 재배치
마을이 좁아 보인다는 피드백에 따라, 월드 크기(카메라 스크롤)를 키우는 대신 **구역 분리 + 배치 재정리**로 해결했어요.

- **원인**: 밭 3개가 마을 중심부의 넓은 자리를 차지하고 있던 게 가장 큰 원인이었음.
- **해결**: 던전/필드와 같은 패턴으로 완전히 독립된 새 공간 "마을 외곽 텃밭"을 추가하고, 밭을 전부 그쪽으로
  이전(`refreshFarmPlotVisual`이 이제 `isInsideOutskirts`일 때만 보여줌, F키 상호작용도 그 공간에서만 동작).
  겸사겸사 밭도 3개 → 5개로 늘림.
- `gameConfig.js`: `VILLAGE_EXTENSIONS.outskirts_farm` 신설 (이름/색/마을 내 입구 좌표).
  `FARM_PLOTS` 좌표를 텃밭 내부 좌표로 재정의, `HUNTING_GROUNDS`/`DUNGEONS` 좌표도 여유 있게 재배치.
- `GameScene.js`: `enterOutskirts()`/`exitOutskirts()` 추가 (던전/필드 출입 패턴과 동일), 메인 마을 분기에
  "마을 외곽 텃밭 입구(G키)" 근접 체크 추가, `isIndoors()`/`setOutdoorObjectsActive()`에 텃밭 반영.
- NPC/건물 좌표도 전체적으로 더 널찍하게 재배치 (`npcPositions`, `housePositions`).
- **참고**: 좌표는 겹치지 않도록 계산해서 넣었지만 실제 게임 화면으로 직접 확인은 못 했어요.
  막상 플레이해보고 뭔가 겹치거나 어색하면 좌표만 미세 조정하면 돼요.

## 15. 버그 수정 - 마법사 R키 광역 스킬이 항상 "몬스터 없음"으로 실패하던 문제
- **원인**: `CLASS_AOE_SKILLS.mage` 설정에 `radius`나 `maxTargets`가 아니라 `range`라는 다른 필드명을
  써놔서, `useAoeSkill()`의 `if (skill.radius) ... else if (skill.maxTargets) ...` 분기 어디에도
  걸리지 않아 항상 0마리 적중으로 처리됐음 (몬스터가 실제로 있어도 항상 실패 메시지만 뜸).
- **수정**: `range: Infinity` → `radius: Infinity`로 필드명 수정. 반경이 무한대라 사실상
  "현재 공간의 몬스터 전부"를 때리는 원래 의도대로 동작함. 다른 5개 직업(전사/궁수/성직자/도적/소환사)
  설정은 처음부터 올바른 필드명을 쓰고 있어서 영향 없었음.
- **관련 파일**: `gameConfig.js`만 수정 (`GameScene.js`의 `useAoeSkill()` 로직은 변경 없음).

## 16. 동서남북 필드(사냥 필드) 넓히기 - 카메라 스크롤 적용
마을은 건물/NPC 좌표가 복잡하게 얽혀있어서 카메라 스크롤 대신 구역 분리+재배치로 해결했지만,
필드(북/남/동/서)는 몬스터만 있는 텅 빈 전투 공간이라 그냥 공간 자체를 키우고 카메라가
플레이어를 따라다니게(스크롤) 하는 쪽이 훨씬 간단하고 자연스러웠어요.

- **공간 크기**: 800×600 → **1600×1200**으로 4배 확장 (`FIELD_WORLD_WIDTH`/`FIELD_WORLD_HEIGHT`).
- **카메라**: 필드 입장 시 `cameras.main.startFollow(player, true, 0.08, 0.08)`로 부드럽게 플레이어를
  따라가도록 하고, 퇴장 시 `stopFollow()` + 스크롤/경계를 마을 기준(800×600)으로 복원.
- **물리 경계**: 입장 시 `physics.world.setBounds`를 필드 크기로, 퇴장 시 마을 경계(`VILLAGE_WORLD_BOUNDS`)로
  복원. 마을 경계값을 상수로 빼서 여기저기 하드코딩되지 않게 정리.
- **몬스터 배치**: 넓어진 공간 전체(가장자리 150px 여백)에 골고루 분산해서 스폰하도록 변경.
- **몬스터 수 증가**: 공간이 넓어진 만큼 각 필드의 몬스터 수도 늘림
  (북: 10→17마리, 남: 6→10마리, 동: 6→10마리, 서: 5→8마리).
- **버그 수정**: `hpText`(좌상단 HP 표시)에 `setScrollFactor(0)`이 빠져 있던 걸 발견해서 추가함.
  이게 없었으면 카메라가 움직일 때 HP 글씨가 화면에 고정되지 않고 같이 흘러갔을 것.
- **알려진 자잘한 한계**: 마을의 바닥 격자무늬(Graphics로 그린 40px 그리드)는 원래 800×600
  영역에만 그려져 있어서, 필드의 넓어진 나머지 영역은 격자 없이 단색 배경으로 보여요
  (사냥터/던전도 원래 격자가 없어서 크게 어색하진 않을 거예요).
- 사냥터(HUNTING_GROUNDS)/던전(DUNGEONS)은 이번 범위에 포함 안 했어요. 필요하면 같은 방식으로 넓힐 수 있어요.
