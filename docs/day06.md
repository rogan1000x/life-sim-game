# Day 06 - 골드 시스템 + 저장/불러오기 + 시작 화면 + NPC 상점

## 오늘 배운 것
- 확장 가능한 데이터 구조에 새 속성(sellPrice) 추가하는 방법
- localStorage를 이용한 게임 상태 영구 저장
- Phaser useEffect를 조건부로 실행시켜 게임 시작 시점을 제어하는 방법
- 브라우저 AudioContext 정책과 사용자 상호작용(user gesture)의 관계
- SVG를 React 컴포넌트 안에 인라인으로 삽입해 배경 일러스트 구현
- 구매(Buy)와 사용(Use)을 분리하는 아이템 시스템 설계

## 오늘 한 것

### 1. 골드 시스템
ENTITY_TYPES 각 항목에 sellPrice 속성을 추가하여, 자원 채집이나 몬스터 처치 시 
난이도에 비례한 골드를 획득하도록 구현

### 2. 저장/불러오기 시스템 (localStorage)
레벨, 경험치, HP, 스탯, 골드, 인벤토리를 하나의 객체로 묶어 localStorage에 저장. 
상태가 변경될 때마다 자동으로 저장되어 별도의 저장 버튼 없이도 진행 상황이 유지됨

### 3. 게임 시작 화면 추가
페이지 로드 시 Phaser 게임이 즉시 실행되지 않고, 시작 버튼이 있는 화면을 먼저 보여줌. 
버튼 클릭 시점에 useEffect가 트리거되어 게임이 생성되며, 이는 브라우저의 
AudioContext 자동재생 정책과도 맞물려 경고 없이 자연스럽게 사운드가 시작됨

### 4. 시작 화면 배경 일러스트
게임의 채집/자연 컨셉에 맞춰 숲 풍경 SVG를 제작하여 시작 화면 배경으로 인라인 삽입

### 5. NPC 상점 시스템
NPC와 대화하던 상호작용을 상점으로 확장. E키로 NPC 근처에서 상점 창을 열고, 
골드로 포션을 구매할 수 있음

처음에는 구매 즉시 아이템 효과가 적용되도록 만들었으나, 진짜 아이템 시스템처럼 
구매(Buy)와 사용(Use)을 분리하는 것이 더 자연스럽다는 피드백을 받아 개선함:
- 구매 시: 골드 차감 + 인벤토리에 아이템 저장
- 사용 시: 인벤토리에서 아이템 소모 + 실제 효과(HP 회복) 적용

인벤토리 표시 로직도 개선하여, 자원(나무 등)과 상점 아이템(포션)을 구분하고 
상점 아이템에만 사용 버튼이 보이도록 처리

## 트러블슈팅

### saveGame 함수가 호출되지 않는 문제
함수를 수정하는 과정에서 syncStatsToReact 함수 내부에 같은 이름의 함수가 
중첩되어 정의되는 실수가 발생함. saveGame() 호출 코드가 실행되지 않는 
안쪽 함수 안에 갇혀 저장이 되지 않았음. 중복 함수를 제거하고 
올바른 위치로 병합하여 해결

### 교훈
함수를 부분 수정할 때는 함수 전체 범위를 확인하고, 기존 코드와 
새 코드가 겹치거나 중첩되지 않는지 점검해야 함

## 코드 작성 규칙 추가
새로 추가하는 함수/변수에는 역할을 설명하는 한 줄 주석을 반드시 포함하기로 함. 
특히 왜 그렇게 처리하는지(예: 구매와 사용을 왜 분리했는지) 이유도 함께 명시
