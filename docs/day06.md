# Day 06 - 골드 시스템 + 저장/불러오기 + 시작 화면

## 오늘 배운 것
- 확장 가능한 데이터 구조에 새 속성(sellPrice) 추가하는 방법
- localStorage를 이용한 게임 상태 영구 저장
- Phaser useEffect를 조건부로 실행시켜 게임 시작 시점을 제어하는 방법
- 브라우저 AudioContext 정책과 사용자 상호작용(user gesture)의 관계
- SVG를 React 컴포넌트 안에 인라인으로 삽입해 배경 일러스트 구현

## 오늘 한 것

### 1. 골드 시스템
ENTITY_TYPES 각 항목에 sellPrice 속성을 추가하여, 자원 채집이나 몬스터 처치 시 
난이도에 비례한 골드를 획득하도록 구현. 나무는 5골드, 늑대는 25골드처럼 
위험도와 가치가 비례하게 설계함

### 2. 저장/불러오기 시스템 (localStorage)
레벨, 경험치, HP, 스탯, 골드, 인벤토리를 하나의 객체로 묶어 localStorage에 저장. 
상태가 변경될 때마다(syncStatsToReact 호출 시) 자동으로 저장되도록 하여 
별도의 저장 버튼 없이도 진행 상황이 유지되게 함

게임 시작 시에는 저장된 데이터가 있는지 확인하고, 있으면 그 값으로 
변수들을 초기화하여 이어하기가 가능하도록 처리

### 3. 게임 시작 화면 추가
페이지 로드 시 Phaser 게임이 즉시 실행되지 않고, 시작 버튼이 있는 
화면을 먼저 보여주도록 개선. 버튼 클릭 시점(gameStarted state 변경)에 
useEffect의 의존성 배열을 트리거하여 그때 비로소 게임이 생성되게 함

이 방식은 브라우저의 AudioContext 자동재생 정책과도 맞물려, 
사용자의 첫 클릭(user gesture) 이후에 사운드 시스템이 생성되므로 
경고 메시지 없이 자연스럽게 시작됨

### 4. 시작 화면 배경 일러스트
게임의 채집/자연 컨셉에 맞춰 숲 풍경 SVG를 제작하여 시작 화면 배경으로 
인라인 삽입. 별도 이미지 파일 없이 코드 안에서 벡터 그래픽으로 
구현하여 파일 관리 부담 없이 시각적 완성도를 높임

## 트러블슈팅

### saveGame 함수가 호출되지 않는 문제
함수를 수정하는 과정에서, syncStatsToReact 함수 내부에 같은 이름의 
함수가 중첩되어 정의되는 실수가 발생함. 그 결과 saveGame() 호출 코드가 
실행되지 않는 안쪽 함수 안에 갇혀버려 저장이 되지 않았음

해결: 중첩된 중복 함수를 제거하고, saveGame 호출을 원래 함수의 
올바른 위치로 병합함

### 교훈
함수를 부분 수정할 때는 반드시 함수 전체 범위를 확인하고, 
기존 코드와 새 코드가 겹치거나 중첩되지 않는지 점검해야 함
