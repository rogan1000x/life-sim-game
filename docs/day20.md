# Day 20 - 동서남북 별도 필드 시스템 + 콜라이더 누적 버그 대장정

## 오늘 배운 것
- Phaser에서 `physics.add.overlap()`이나 `physics.add.collider()`로 만든 콜라이더는,
  그 대상 오브젝트가 destroy되어도 콜라이더 자체는 자동으로 정리되지 않는다는 것.
  같은 상황(동료 재소환, 집 재입장 등)에서 콜라이더를 매번 새로 만들기만 하고
  이전 것을 명시적으로 지우지 않으면, "이미 사라진 대상을 가리키는 유령 콜라이더"가
  계속 쌓여서 다음 프레임에 물리 엔진이 `undefined`를 읽으려다 에러가 난다는 것
- 이런 유의 에러(`Cannot read properties of undefined (reading 'isParent')`)는
  발생 시점(collideObjects 내부)만 봐서는 원인을 바로 알기 어렵고, "어떤 동작이
  반복될 때마다 오브젝트를 새로 만들면서 이전 참조를 안 지우는가"를 거슬러
  올라가며 찾아야 한다는 것 - 여러 차례 "몬스터 제거 방식"을 고쳐도 에러가
  똑같이 재현된 것 자체가 몬스터 쪽이 원인이 아니라는 단서였음
- `physics.add.overlap()`/`collider()`가 반환하는 값은 `Collider` 객체이고,
  여기에 `.destroy()`를 호출하면 그 콜라이더 하나만 안전하게 물리 세계에서
  제거할 수 있다는 것 - 이 반환값을 변수에 저장해두는 습관이 중요함
- 그룹(Group)에서 오브젝트를 제거할 때, 오브젝트에서 직접 `.destroy()`를 부르는 것보다
  `group.remove(child, true, true)`를 쓰는 것이 그룹 내부 목록과 물리 엔진 양쪽을
  일관되게 정리해주는 더 안전한 방법이라는 것
- 별도 공간(필드/던전)에서 나갈 때는 "그 공간의 오브젝트를 먼저 확실히 정리"하고 나서
  "나머지 오브젝트를 다시 활성화"하는 순서가 중요함 - 반대 순서로 하면 아주 짧은
  순간 오브젝트가 "다시 켜졌다가 곧바로 파괴"되는 타이밍이 생겨 물리 엔진이 꼬일 수 있음

## 오늘 한 것

### 1단계: 지역 기반 필드 분리 1차 시도 (FIELD_BOUNDS)
"마을에 몬스터가 돌아다니는 게 어색하다"는 지적에 따라, 처음엔 같은 지도 안에서
좌표 범위(FIELD_BOUNDS)를 나눠 몬스터(늑대/고블린/도적)만 특정 구역 안에서
스폰/리스폰되도록 구현하고, 위험지역 경계를 붉은 점선으로 표시함

### 2단계: 요구사항 정정 - 완전히 별도의 공간으로
사용자가 원한 건 "같은 지도 안의 구역 나누기"가 아니라 "동서남북 각각 다른 테마를
가진, 지금 보이는 마을과는 완전히 분리된 별도의 필드"였음. FIELD_BOUNDS를
FIELD_ZONES로 전면 교체하여, 북쪽 숲/남쪽 평야/동쪽 산악/서쪽 해안 4개의 독립
공간을 설계함. 각 필드는 고유한 배경색과 몬스터 구성을 가지며, 던전처럼 완전히
다른 좌표 공간으로 이동하지만 던전과 달리 클리어 조건 없이 H키로 언제든 나갈 수
있는 자유로운 공간으로 구현함

### 3단계 (트러블슈팅 대장정): 콜라이더 누적 버그
필드 시스템을 만드는 과정에서 `Cannot read properties of undefined (reading 'isParent')`
에러가 반복적으로 발생함. 다음과 같은 순서로 원인을 좁혀나감:
1. 처음엔 몬스터를 그룹에서 제거하는 방식(`entity.destroy()`)이 원인이라 추정하고,
   별도 그룹(fieldEntities)을 만들어 `clear(true, true)`로 정리하도록 수정 → 에러 재현
2. `exitField()`에서 "필드 몬스터 정리"와 "실외 오브젝트 재활성화"의 순서를
   바꿔봄(정리를 먼저) → 에러 재현
3. 별도 그룹을 아예 없애고 entities 그룹 하나에 꼬리표(fieldZoneId)로 구분하는
   방식으로 단순화, `group.remove()`로 안전하게 제거하도록 변경 → 여전히 에러 재현
4. 전체 파일을 다시 받아 검토한 끝에 진짜 원인을 발견함: **동료(companion)를
   소환할 때마다(`spawnCompanion`) `physics.add.overlap()`을 새로 만들면서, 이전
   동료를 가리키던 콜라이더를 한 번도 정리하지 않고 있었음.** 동료를 해고→재고용
   하거나 저장 데이터를 불러올 때마다 유령 콜라이더가 계속 쌓여, 필드와 무관한
   시점에도 다음 물리 프레임에서 에러가 발생하고 있었던 것

### 4단계: 근본 원인 수정 및 전체 재작성
`companionOverlapCollider`라는 변수에 콜라이더 참조를 저장해두고, `spawnCompanion()`
호출 시마다 기존 콜라이더를 `.destroy()`로 먼저 정리한 뒤 새로 생성하도록 수정함.
같은 문제가 집/주점의 가구·카운터·리나 콜라이더에도 잠재되어 있어(입장할 때마다
새로 만들면서 퇴장 시 콜라이더 자체는 안 지웠음), `furnitureColliders` 배열로
추적하여 함께 정리하도록 구조를 통일함. 사냥터/던전/필드 몬스터 제거도 전부
`group.remove(entity, true, true)` 방식으로 통일함. 이 모든 수정을 반영해
GameScene.js 전체를 다시 한번 재작성함

## 완성된 시스템 요약 (Day 20 전체)
- 마을 지도에는 더 이상 늑대/고블린/도적이 등장하지 않고, 사슴/토끼만 돌아다님
- 동서남북 4개의 완전히 분리된 필드(숲/평야/산악/해안)가 생기고, 각각 다른
  몬스터 구성과 배경색을 가짐
- 필드는 던전과 달리 클리어 조건 없이 자유롭게 드나들 수 있음
- 동료 재소환, 집/주점 출입, 필드/던전 출입 시 발생하던 고질적인 콜라이더 누적
  버그가 근본적으로 해결됨 (콜라이더 참조를 저장해두고 재생성 전 정리하는 패턴 확립)
