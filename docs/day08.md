# Day 08 - 캐릭터/NPC 이미지 적용 (도형 → 스프라이트 전환)

## 오늘 배운 것
- Phaser의 spritesheet 로딩 방식과 frameWidth/frameHeight 지정 방법
- this.anims.create로 여러 프레임을 순서대로 재생하는 애니메이션 정의 방법
- 스프라이트시트 프레임 번호는 이미지의 그리드를 행 우선(row-major)으로 세는 것,
  즉 "열 + 행 x 전체 열 수" 공식으로 원하는 프레임을 골라 쓸 수 있다는 것
- 이미지 뷰어의 체커보드(투명 표시용 바둑판 무늬)가 스크린샷 과정에서
  실제 픽셀로 고정되어버릴 수 있다는 것, 그리고 이런 경우와
  실제 알파 채널이 살아있는 파일을 구분하는 방법(PNG 모드, transparency 정보 확인)
- setDisplaySize 대신 setScale을 써야 픽셀아트 캐릭터가 찌그러지지 않는다는 것

## 오늘 한 것

### 1단계: 이미지 적용 방식 결정
움직이는 이미지가 필요하다는 목표 아래, 코드로 만드는 애니메이션과
실제 스프라이트시트 애니메이션 중 스프라이트시트 방식으로 결정함.
성능 우려가 있었으나, 이 게임 규모(오브젝트 수十개 수준)에서는
스프라이트시트를 써도 문제없다는 걸 확인하고 진행함

### 2단계: 첫 번째 캐릭터 에셋 시도 (실패, 원인 파악)
사용자가 스크린샷 형태로 공유한 이미지 두 개를 분석한 결과,
1) 실제 다운로드한 zip 파일이 아니라 이미지 뷰어 화면을 스크린샷 찍은 것이었고
2) 그 결과 투명 배경 표시용 체커보드 무늬가 실제 픽셀로 고정되어
   게임 배경색과 다른 사각형이 노출되는 문제가 있었음
3) 처음엔 "가로 4프레임 = 달리기 동작"으로 추정했으나,
   사용자 확인 결과 실제로는 "가로 4열 = 4방향, 세로 3행 = 각 방향의 프레임"
   구조였음 (왼쪽/아래/위/오른쪽 순서로 확인)

flood fill 기반 자동 배경 제거를 임시로 적용해서 진행은 했으나,
근본적으로는 알파 채널이 있는 원본 파일이 필요하다는 결론을 냄

### 3단계: 실제 알파 채널이 있는 타일맵 파일 확보
사용자가 새로 공유한 tilemap.png 파일은 PNG 팔레트 모드에
실제 transparency 정보가 포함된 원본 에셋으로 확인됨.
이 파일 안에 바닥/벽 타일, 가구/장식, 그리고 4방향 x 18종의
캐릭터 그리드가 포함되어 있음을 확인함

이 캐릭터 그리드는 방향당 프레임이 1장뿐이라(걷기 동작 없음),
방향 전환만 되는 형태로 최종 적용하기로 함

### 4단계: 플레이어 캐릭터에 적용
1번 캐릭터를 선택하여 4방향(왼쪽/아래/위/오른쪽) 스프라이트시트로 잘라냄.
GameScene.js에 아래 구조로 반영:
- preload()에서 16x16 spritesheet로 로드
- 방향별 프레임 번호를 this.directionFrames로 관리
- handleMovement()에서 이동 방향이 바뀔 때만 setFrame으로 프레임 전환
  (걷기 동작이 없는 에셋이라 애니메이션 대신 방향 전환만 처리)

### 5단계: NPC 확장 (기존 1명 → 3명)
기존에 파란 사각형 하나였던 NPC를 실제 캐릭터 이미지로 교체하면서,
동시에 2~3명으로 늘리는 작업 진행. 타일맵에서 2/3/4번 캐릭터를 선택하여
각각 별도의 스프라이트시트로 추출함

gameConfig.js의 NPC_DATA를 villager 단일 항목에서
villager1/villager2/villager3 세 항목으로 확장하고, color 대신
spriteKey를 사용하도록 구조 변경

GameScene.js에는 집(houses)과 동일한 "위치 배열 + 통합 함수" 패턴을 적용:
- npcPositions 배열에 위치와 타입만 추가하면 몇 명이든 배치 가능
- createNpc() 통합 함수가 NPC_DATA를 참조해 스프라이트를 생성
  (NPC는 움직이지 않으므로 "아래를 보는" 1번 프레임으로 고정)

## 완성된 시스템 요약 (Day 08 전체)
- 플레이어 캐릭터가 도형에서 4방향 스프라이트 이미지로 교체됨
  (걷기 동작 없이 방향 전환만 되는 형태)
- NPC가 사각형 1개에서 실제 캐릭터 이미지 3명으로 확장됨
  (villager1/villager2/villager3, 각자 다른 이름과 대사 보유)
- 집(houses)에 이어 NPC도 "위치 배열 + 통합 함수" 패턴으로 통일되어,
  앞으로 캐릭터/NPC를 늘릴 때 데이터와 위치만 추가하면 되는 구조가 됨
