# Day 09 - 집 내부 이미지 적용 + git 대용량 파일 트러블슈팅

## 오늘 배운 것
- Phaser의 tileSprite로 이미지 한 장을 넓은 영역에 반복 배치하는 방법
  (바닥 전체를 채우기 위해 큰 이미지를 따로 만들 필요 없이, 타일 하나만 있으면 됨)
- setDepth로 오브젝트 간 렌더링 순서(위/아래)를 지정하는 방법
- git이 100MB 넘는 파일이 포함된 push를 거부한다는 것, 그리고
  그 원인이 "지금 커밋"이 아니라 "과거 커밋 히스토리 전체"에 있을 수 있다는 것
- git filter-branch로 히스토리 전체에서 특정 파일을 완전히 제거하는 방법과,
  그 과정에서 필요한 후속 정리(refs/original 삭제, reflog expire, gc)
- filter-branch 실행 전에는 작업 디렉토리가 깨끗해야 한다는 제약 조건

## 오늘 한 것

### 1단계: 집 내부 바닥/가구 에셋 선정
기존 타일맵 파일에서 바닥 타일 후보 2종(나무색, 회색)과
가구 후보 4종(소파, 서랍장 2종, 초록 선반)을 잘라내어 확인함

### 2단계: "여러 채의 집" 구조를 살려 조합 다양화
집이 하나가 아니라 여러 채 지원되는 구조라는 점을 살려서,
바닥/가구 조합을 다르게 한 집 4채로 확장하기로 함:
- 내 집: 나무 바닥 + 소파
- 이웃집: 회색 바닥 + 서랍장1
- 여행자의 집: 나무 바닥 + 서랍장2
- 창고: 회색 바닥 + 초록 선반

### 3단계: BUILDING_TYPES 구조 변경
기존에는 interiorColor(단색 배경)와 furniture의 color(사각형)로 표현되던 것을,
floorTile(바닥 이미지 키)과 furniture의 spriteKey(가구 이미지 키)로 변경함.
이 구조 변경 덕분에 새 집을 늘릴 때도 데이터만 추가하면 되는
기존 패턴(카테고리 기반 데이터 + 통합 함수)이 그대로 유지됨

### 4단계: toggleHouse()에 바닥 타일 렌더링 추가
실내 진입 시 tileSprite로 바닥 전체를 채우고, 가구는 사각형 대신
실제 이미지 스프라이트로 교체. 실외로 나갈 때는 바닥 타일 오브젝트를
확실히 destroy하여 다음에 다른 집에 들어갔을 때 이전 바닥이
남지 않도록 처리함

### 5단계 (예상치 못한 트러블슈팅): git push 거부 문제
day08 작업을 커밋 후 push하는 과정에서 GitHub가 100MB 넘는 파일이
포함되어 있다며 push를 거부함. 확인 결과, 게임과 무관한
MoneyManager-1.8.20.exe(약 134MB) 파일이 실수로
public/assets/npc/ 폴더에 섞여 들어가 있었던 것으로 확인됨

해결 과정에서 Python(pip)과 Java 둘 다 설치되어 있지 않아
git-filter-repo나 BFG 같은 별도 도구를 쓸 수 없었고,
git에 기본 내장된 filter-branch로 해결함. 이 과정에서:
- 처음엔 작업 디렉토리에 커밋 안 된 변경사항이 있어 실행이 막혔고,
  커밋 후 재시도하여 해결
- filter-branch 실행 후 refs/original 백업이 남아있어 파일이 계속
  보였고, 백업 정리(reflog expire, gc) 후에야 완전히 제거됨
- 최종적으로 force push 성공, 저장소가 정상 상태로 복구됨

재발 방지를 위해 .gitignore에 *.exe 패턴 추가를 권장함

## 완성된 시스템 요약 (Day 09 전체)
- 집 4채가 각기 다른 바닥/가구 조합으로 배치됨
- 실내 진입/퇴장 시 바닥 타일이 집마다 올바르게 교체됨
- git 저장소가 대용량 파일 없이 정상적으로 push 가능한 상태로 복구됨
