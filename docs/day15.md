# Day 15 - 퀘스트 시스템 + 캐릭터 설정 문서화 + 동료 고용 시스템

## 오늘 배운 것
- 객체 리터럴(`{ ... }`) 안에는 `export const` 같은 독립적인 선언문을 끼워 넣을 수 없다는 것 -
  export 문은 항상 다른 객체/배열의 "바깥"에 있어야 하고, 안에 넣으면 문법 자체가 깨져서
  파싱 에러가 난다는 것을 실제 에러로 확인함
- 같은 이름(예: QUEST_TEMPLATES)을 파일에 두 번 선언하면 "이미 선언됨" 에러가 난다는 것,
  그리고 이런 중복은 이전 안내가 잘못된 위치를 짚었을 때 "지우고 새로 넣기"가 아니라
  "그냥 또 추가하기"가 되면서 생길 수 있다는 것 - 검색(Ctrl+F)으로 중복 여부를 먼저
  확인하는 습관이 필요하다는 것
- JSX 안에서 일반 텍스트처럼 `/* 주석 */`을 쓰면 화면에 그대로 노출되거나 문법 경고가
  발생하고, 반드시 `{/* 주석 */}`처럼 중괄호로 감싸야 한다는 것
- "재고에 따라 가격이 변하는" 시장 시스템을 모든 아이템에 일괄 적용하면, 재입고 개념이
  없는 아이템(예: 주점에서 매번 새로 만들어주는 음식)에는 맞지 않는다는 것 - 이런 경우
  unlimitedStock 같은 예외 플래그를 두어 일부 아이템만 재고 계산에서 제외하는 방식이 필요함
- 도형/스프라이트를 굳이 이미지 자산 없이도 배치할 수 있다는 것(카운터를 rectangle로),
  그리고 이미 불러온 스프라이트를 다른 NPC에 재사용하면 새 이미지 없이 빠르게 캐릭터를
  늘릴 수 있지만, 같은 그림이 여러 곳에 등장하면 시각적으로 혼동을 줄 수 있다는 것
- 캐릭터의 이름/나이/성격/말투 같은 설정을 코드 주석이 아니라 별도 문서로 분리해두면,
  다음 세션에서 새 대사를 쓰거나 새 캐릭터를 만들 때 톤을 일관되게 유지하기 쉽다는 것

## 오늘 한 것

### 1단계: 퀘스트 시스템 구현
주점(용병 길드) 2단계로 퀘스트 시스템을 구현함. QUEST_TEMPLATES에 5개의 고정 퀘스트를
정의(나무/돌/늑대 가죽/토끼 고기/당근 모으기)하고, 각각 인벤토리 아이템 개수 조건과
골드+경험치 보상을 가짐. GameScene에 activeQuestIds(수락한 퀘스트 목록)를 추가하고
acceptQuest/turnInQuest 함수로 수락과 제출을 처리하도록 구현. 완료 시 아이템은
소모되고, 퀘스트는 다시 수락 가능한 반복형으로 만듦

### 2단계 (트러블슈팅): QUEST_TEMPLATES 위치/중복 문제
처음 안내한 위치(BUILDING_TYPES 객체 내부, tavern 항목 근처)가 실제로는 객체 리터럴
"안쪽"이라 export 문을 끼워 넣을 수 없는 위치였고, 이로 인해 파싱 에러가 발생함.
이후 "BUILDING_TYPES 객체 앞"으로 다시 안내했으나, 사용자가 이전 잘못된 위치의
코드를 지우지 않고 새 코드를 추가하면서 QUEST_TEMPLATES가 파일에 두 번 선언되는
문제가 생김. 최종적으로 파일 전체를 받아 확인하고, 중복 없이 한 곳에만 정상적으로
위치한 상태를 확인함

### 3단계: 밭이 실내에서도 보이는 문제 수정
집/주점에 들어가도 밭(작물, 가격표)이 화면에 계속 보이는 버그를 발견. 원인은 밭을
다시 그려주는 5초 주기 타이머가 isInsideHouse 상태를 전혀 확인하지 않고 무조건
다시 그리고 있었기 때문. 이를 계기로 "오브젝트가 보일 때마다 매번 따로 설정해야
하는" 번거로움을 지적받아, refreshEntityVisual() 패턴과 동일하게
refreshFarmPlotVisual() 함수 자체가 실내 여부를 판단해 알아서 숨기도록 구조를
통일함 - 이후로는 이 함수를 호출하는 곳(타이머든 건물 출입이든) 어디서든 별도
처리 없이 올바르게 동작하게 됨

### 4단계: 건물 이름 표시 UI 추가
건물에 들어갔을 때 화면 위에 그 건물 이름("주점", "내 집" 등)이 표시되도록
buildingNameText를 추가함. 평소엔 숨겨져 있다가 toggleHouse()에서 실내 진입/퇴장
시점에 맞춰 표시/숨김을 전환하도록 구현

### 5단계: 주점 NPC(길드 담당자) 추가
주점 안에 카운터(사각형 도형)와 그 뒤에 서있는 NPC를 추가함. 처음엔 기존
npc_villager1 이미지를 재사용했으나, 실외의 마을 주민과 그림이 겹쳐 혼동을 줄 수
있다는 점을 사용자에게 먼저 알림

### 6단계: 캐릭터 컨셉 설정 - 리나
사용자 요청으로 길드 담당자에게 실제 캐릭터 컨셉을 부여함: 이름 리나, 19세,
처음 온 용병/여행자를 살갑게 챙기는 다정한 주점 언니 컨셉. 반말 섞인 친근한 말투로
격려/걱정을 표현하는 대사 5개를 작성함. 스프라이트는 villager2 이미지를 임시로
재사용하기로 함(실외의 수다쟁이 이웃과 겹치는 문제가 있으나, 전용 그림을 구할 때까지
보류하기로 사용자와 합의함)

### 7단계: 캐릭터 설정 문서화
NPC/캐릭터 설정이 코드 주석과 대화 속에만 흩어져 있어 다음 세션에서 일관성을
유지하기 어렵다는 점을 논의. docs/characters.md라는 별도 문서를 만들어 villager1~3과
리나의 이름/역할/성격/말투/스프라이트 정보를 한 곳에 정리함. 앞으로 새 대사를 쓰거나
새 캐릭터를 만들 때 이 문서를 먼저 참고하기로 함

### 8단계: 동료 고용 시스템 구현
주점 3단계로 동료 고용 시스템을 구현함. COMPANION_TYPES에 '떠돌이 동료' 1종을
정의(스프라이트는 실외 떠돌이 여행자와 임시로 공유, 고용비 0G 50S, 전투 보너스
데미지 4). GameScene에 hiredCompanionId/companionSprite 상태를 추가하고:
- hireCompanion/dismissCompanion으로 고용/해고 처리
- updateCompanionFollow()가 매 프레임 플레이어와의 거리를 계산해 따라오게 하고,
  이동 방향에 따라 플레이어와 같은 방향 프레임 규칙을 적용
- 몬스터 공격 시 동료가 150px 이내에 있으면 보너스 데미지가 함께 들어가도록 처리
- 실내 진입/퇴장 시 동료를 숨기고 다시 보이게 하는 처리, 저장/불러오기 시 동료
  상태도 유지되도록 구현

### 9단계 (트러블슈팅): eslint 경고 및 주점 음식 재고 문제
- JSX 안에서 `{/* */}`가 아니라 일반 텍스트처럼 주석을 써서 발생한 경고를 수정함
- 주점 음식(빵, 스튜)이 한 번 재고 10개를 다 팔리면 더 이상 안 채워지는 문제를
  발견함. 원인은 모든 상점 아이템에 공통으로 적용되는 재고 기반 가격 시스템이
  음식에도 그대로 적용됐기 때문. 음식은 재입고 개념이 필요 없는 "매번 새로 만들어주는
  서비스"라는 설정에 맞게, unlimitedStock 플래그를 추가해 재고 계산에서 제외하도록
  gameConfig.js/GameScene.js/App.js를 함께 수정함

## 완성된 시스템 요약 (Day 15 전체)
- 주점에서 퀘스트를 수락/완료할 수 있고, 완료 후 반복 수락이 가능함
- 밭의 실내/실외 표시 로직이 entities와 동일한 패턴으로 통일되어, 앞으로 비슷한
  숨김 버그가 구조적으로 재발하기 어려워짐
- 건물에 들어가면 화면에 건물 이름이 표시됨
- 주점에 리나라는 이름과 컨셉을 가진 NPC가 카운터에 서있고, 대사로 대화 가능함
- 캐릭터 설정을 정리한 docs/characters.md 문서가 생성됨
- 동료를 골드로 고용해서 데리고 다닐 수 있고, 전투를 거들어주며, 해고도 가능함
- 주점 음식은 재고 걱정 없이 무제한으로 구매 가능함
