# Day 18 - 장비 슬롯 확장, 액티브 스킬, 동료 AI 전면 개편, 사냥터/던전 시스템

## 오늘 배운 것
- 여러 차례의 부분 수정이 누적되면 JSX 같은 중첩 구조가 특히 쉽게 깨질 수 있고,
  이럴 땐 부분 수정을 더 시도하기보다 파일 전체를 처음부터 다시 작성하는 게
  오히려 더 빠르고 정확하다는 것
- "실내 여부" 같은 공통 판단 기준이 여러 곳(집, 던전 등)으로 늘어날수록,
  isInsideHouse 하나만 확인하던 곳들을 전부 찾아 고치는 대신 isIndoors() 같은
  통합 판단 함수를 만들어 그 함수만 확장하면 새로운 "실내 종류"가 늘어나도
  각 호출부는 손댈 필요가 없어진다는 것
- 사냥터/던전처럼 구조가 비슷한 두 시스템은, 등급 데이터 모양(shape)을 동일하게
  맞춰두면 몬스터 생성 로직(createHuntMonster) 하나를 그대로 재사용하면서
  encounterType 같은 구분값만 추가하는 식으로 코드 중복 없이 확장할 수 있다는 것
- 초기화 코드는 "어디에 있는지"가 매우 중요해서, constructor(어떤 상황에서도
  게임 시작 시 한 번 실행)와 toggleHouse의 특정 분기(특정 조건에서만 실행)를
  헷갈리면, 겉보기엔 비슷한 위치라도 실제로는 전혀 다른 시점에 실행되어
  "아직 준비 안 된 값을 참조하는" 에러가 난다는 것
- 동료 같은 NPC성 유닛도 플레이어와 같은 방식(체력, 사망/부활, 우선순위 기반
  행동 로직)으로 다루면, 새로운 시스템을 처음부터 짜지 않고 기존 패턴을
  재사용할 수 있다는 것

## 오늘 한 것

### 1단계: 장비 슬롯 9종 확장
기존 weapon 슬롯 하나뿐이던 장비 시스템을 머리/몸통/바지/장갑/신발/무기/방패/반지/목걸이
9개 슬롯으로 확장함. EQUIPMENT_SLOTS 데이터로 슬롯 목록을 관리하고, equipped 객체를
이 목록을 순회하며 자동으로 만들도록 구현. 각 슬롯(무기 제외)에 기본 아이템 2종씩
채우고, 반지/목걸이는 내구도를 사실상 무제한(999)으로 설정함. 예전 저장 파일에
weapon 슬롯만 있어도 새 슬롯들이 안전하게 병합되도록 처리함

### 2단계: 액티브 스킬(Q키) 시스템 도입
직업당 1개씩 총 6개의 발동형 스킬을 추가함 - 전사(돌진 베기), 궁수(관통 사격),
마법사(파이어볼, 광역), 성직자(치유의 빛, 자힐), 도적(그림자 일격, 무조건 치명타),
소환사(소환수 강화, 동료 버프). 쿨타임은 지능 스탯에서 나오는 재사용 대기시간
감소가 실제로 처음 적용되는 곳이 됨. 화면 오른쪽 아래에 쿨타임 UI를 추가하고,
몬스터 처치 로직을 defeatMonster()로 분리해 스페이스바 공격과 액티브 스킬
양쪽에서 재사용할 수 있게 구조를 정리함

### 3단계 (트러블슈팅): App.js 구조 붕괴 및 전체 재작성
여러 차례의 부분 수정이 누적되면서 App.js의 JSX 중첩 구조가 깨짐(#phaser-game
div가 일찍 닫히고, 이후 패널들이 최상위에 붕 뜬 상태). 부분 수정 대신 전체 파일을
처음부터 다시 작성해 구조를 복구함. 이후 반복적으로 겪은 "부분 수정이 실제 파일과
어긋나는" 문제 예방을 위해, 이후로는 규모가 큰 변경 시 파일 전체를 새로 작성하는
방식을 더 적극적으로 사용하기로 함

### 4단계: GM(Admin) 기능 개선
레벨/직업 초기화 버튼을 삭제하고, 대신 레벨을 원하는 숫자로 직접 입력하는 기능과
직업을 즉시 자유롭게 바꾸는 기능(adminSetLevel, adminSetClass)으로 교체함.
기존 chooseClass()와 달리 이미 직업이 있어도 제한 없이 덮어쓸 수 있게 해서
테스트 편의성을 높임

### 5단계: 궁수/마법사 원거리 기본 공격 + 동료 랜덤 직업/자동 스킬
궁수와 마법사의 기본 공격(스페이스바)이 근접(100px)이 아니라 투사체를 날리는
원거리(260px) 방식으로 동작하도록 CLASS_TYPES에 attackType 필드를 추가하고
performRangedBasicAttack()을 구현함. 동료를 고용하면 6개 직업 중 하나가 무작위로
배정되고, 배정된 직업의 액티브 스킬을 동료가 주기적으로 자동 발동하도록
startCompanionAutoSkillTimer/useCompanionAutoSkill을 구현함

### 6단계: 동료 AI 전면 개편 (생존 → 보호 → 능동전투 우선순위)
동료가 그냥 따라만 다니던 방식에서, 실제로 체력을 가지고 전투에 참여하는 존재로
개편함. 몬스터와 부딪히면 데미지를 입고, 체력이 0이 되면 15초간 기절했다가 자동
부활함. 행동 우선순위를 ① 자기 생존(체력 30% 미만이면 도망) ② 플레이어 보호
(플레이어를 위협하는 몬스터 우선 공격) ③ 능동 전투(주변 몬스터 선제 공격)
④ 따라다니기 순으로 구현. 동료 전용 기본 공격(companionBasicAttack)도 별도로 추가함

### 7단계: 로그 시스템 대폭 강화
공격 시 데미지 수치(가하는 피해/받는 피해), 아이템 획득/소실(구매·판매·사용·씨앗
소모·퀘스트 제출 등 전 항목), 경험치 획득량을 전부 로그로 표시하도록
GameScene 전반의 addLog 호출을 정비함. 로그 최대 개수를 4개에서 10개로 늘리고,
최근 5개는 선명하게, 그 이후는 오래될수록 점점 투명해지도록 opacity 계산을
추가해 정보량과 가독성을 함께 확보함

### 8단계: 사냥터 시스템 (등급별 게이트)
F/E/D/C/B/A 6등급의 사냥터 게이트를 도입함. 등급마다 게이트 색이 달라(회색→빨강)
색만 보고 난이도를 짐작할 수 있게 하고, HUNTING_GROUND_RANKS에 등급별 몬스터
강화 배율/보스 체력 배율/레어 드랍 확률/드랍 아이템을 정의함. G키로 게이트에
입장하면 그 자리에 일반 몬스터 4마리+보스 1마리가 스폰되고, 보스는 확대된 크기와
노란빛으로 구분됨. 이 웨이브 몬스터는 일반 몬스터 풀과 분리되어 리젠 없이
처치되면 사라지며, 보스 처치 시 확률적으로 레어 장비를 드랍함. 이전 웨이브가
안 끝나면 같은 게이트 재입장이 막히도록 huntWaveCounts로 관리함

### 9단계 (트러블슈팅): 사냥터 초기화 코드 위치 오류
this.gateObjects 등 사냥터 상태 초기화 코드가 constructor()가 아니라
toggleHouse()의 실외 복귀 분기에 잘못 삽입되어, 게임을 처음 켤 때 아직 한 번도
실행 안 된 상태에서 create()가 이 값을 참조하다 에러 발생. 실제 코드를 받아
정확한 위치(constructor())로 옮겨 해결함

### 10단계: 던전 시스템 설계 및 구현 착수 (미완료, 다음 세션으로 이어짐)
사냥터와 달리 완전히 별도의 공간으로 이동하는 방식의 던전을 설계함. F~A 6등급에
더해 최상위 등급 S/SS/SSS까지 총 9단계(DUNGEON_RANKS)를 정의하고, 같은 사냥터
몬스터 생성 로직(createHuntMonster)을 encounterType('hunt'/'dungeon') 구분으로
재사용하도록 구조를 잡음. 던전은 몬스터를 모두 잡아야 출구 문이 열리는 방식으로
설계했으며, 실내(집/주점) 판단 로직을 isIndoors()로 통합해 사냥터 게이트가
실내에서도 계속 보이던 버그(setOutdoorObjectsActive에 게이트 숨김 처리가
빠져있던 문제)도 함께 수정함. update() 함수 전체를 재구성해 던전 안에서는
NPC/집/밭/게이트 상호작용을 건너뛰고 출구 문 처리만 하도록 분기를 만드는 중
작업이 끊겨, defeatMonster()의 던전 분기 처리와 던전 입장/퇴장 함수
(enterDungeon/handleDungeonExit)는 다음 세션에서 마저 구현하기로 함

## 완성된 시스템 요약 (Day 18 전체)
- 장비 9슬롯(머리~목걸이) 전면 확장
- 직업별 액티브 스킬(Q키) 6종 + 쿨타임 시스템 (재사용 대기시간 감소 스탯 첫 사용처)
- GM 기능으로 레벨 직접 설정, 직업 자유 변경 가능
- 궁수/마법사 원거리 기본 공격, 동료 무작위 직업 배정 + 자동 스킬
- 동료가 체력을 갖고 실제로 전투하며, 생존/보호/전투 우선순위에 따라 행동함
- 데미지/아이템/경험치가 전부 로그로 표시되고, 로그가 10개까지 서서히 흐려지며 쌓임
- 사냥터(F~A 등급 게이트) 시스템 완성 - 웨이브 스폰, 보스, 레어 드랍까지 작동
- 던전 시스템은 데이터/구조 설계까지 진행되었으나 구현 중간에 중단됨 (다음 세션 계속)
